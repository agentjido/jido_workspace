# Documentation instructions

## Docs Kata

| Path | Purpose |
| --- | --- |
| `README.md` | Documentation index and fixed paths. |
| `ROLE.md` | Project responsibilities and reserved decisions. |
| `inbox/` | Material that needs review. |
| `decisions/` | Accepted decisions, reasons, and consequences. |
| `plans/` | Proposed work and verification criteria. |
| `guides/` and `reference/` | Current instructions and system behavior. |
| `lessons/` and `archive/` | Verified findings and historical material. |

Use paths relative to `docs/`. Create a category when it has material.

- Put unprocessed material in the inbox. Record its source, date, and status
  in the intake log. Keep required paths in place and log why.
- Check claims about current behavior against code and tests. Record accepted
  decisions separately from open questions and proposed changes.
- Give reviewed documents a title, purpose, status, review date, and relevant
  links. Prefer an existing page. Update the index and intake log when a page
  moves. Preserve license notices and attribution.
- During maintenance, place or archive reviewed items. Leave unresolved items
  in the inbox with an owner and the next decision or check.
